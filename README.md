# Практикалық жұмыс №7

10-нұсқа: файлдық сақтау. №6 жобаға қауіпсіздік пен health-check қосылды.

Дайын бет: https://cloud-practice-7-variant10.onrender.com/demo

## Нені тексеруге болады

- «Қызмет күйі»: GET /health, қалыпты жағдайда HTTP 200.
- «База күйі»: GET /health/db, база қолжетімді болса 200, қосылым қате болса 503.
- «400 тексеру»: екі міндетті өрісі жоқ POST сұранысы.
- «404 тексеру»: жоқ файлды оқу.
- «Барлық файлды оқу»: GET /api/files.
- Жаңа атау енгізіп POST жіберу: HTTP 201.

Жаңа POST үшін бұрын қолданылмаған атау керек. Бар атауды қайталау HTTP 409 береді.

## Компьютерде іске қосу

1. `npm.cmd install` орындаңыз.
2. `.env.example` файлын `.env` деп көшіріңіз.
3. `.env` ішіне өз базаңыздың DATABASE_URL мәнін енгізіңіз. Сыртқы Render URL қолдансаңыз DATABASE_SSL жолын алып тастаңыз.
4. Базада кесте әлі жоқ болса, `npm.cmd run db:init` орындаңыз.
5. `npm.cmd start` орындаңыз.
6. http://localhost:3003/demo адресін ашыңыз. .env ішінде PORT=3003 берілген болуы керек.

`.env` автоматты оқылады. Оның нақты мәнін GitHub-қа немесе есепке қоспаңыз.

## Бұлттық баптау

№5 және №6 жұмыстағы репозиторий, Web Service және PostgreSQL қолданылды.
Build Command: `npm install`. Start Command: `npm start`.
DATABASE_URL — Render Environment ішінде. Ішкі қосылым үшін DATABASE_SSL=disable.
STUDENT_VARIANT=10, APP_ENV=production.

Сервер іске қосылғанда базаға бірден қосылмайды. Осылайша база істемесе де /health 200 бере алады.
Кестені дайындау командасы іске қосудан бөлек: `npm run db:init`.

## Қате қосылым тәжірибесі

Осы оқу сервисінің DATABASE_URL мәніндегі база атауын уақытша жоқ атауға ауыстырыңыз.
Қайта жариялағаннан кейін /health 200, /health/db 503, ал базаға тәуелді GET /api/files 500 береді.
Журналда уақыт, әдіс, адрес, HTTP коды және DB_HEALTH_ERROR 3D000 оқиғасы көрінеді.
Дұрыс URL-ді қайтарып, қайта жариялаңыз. /health/db және /api/files қайтадан 200 беруі тиіс.
Құпия URL-ді суретте немесе журналда ашпаңыз.

Docker және VM міндетті емес. Негізгі тексерулер Render-де орындалады.
